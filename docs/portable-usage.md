# AASAPI — 主ASIOクロックで複数機器を使う

Windows x64用。主機器の純正ASIO入出力とクロックを使用し、追加WASAPI機器とPC音を主クロックへ追従させる。別の純正ASIOを主クロックへ自動切替しない

## 起動と設定

ライセンスと第三者表記は[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)を参照。商標の登録・使用許諾取得を主張する名称ではない

1. build/aasapi.exeで主画面を開く。従来のbuild/aggregate_gui.exeとaggregate_router.exeも利用可能。ルーティング・機器設定・診断・遅延補正をタブで切り替える。どのタブでも開始／停止、ミュート、音量、常用設定は共通
2. 「機器設定」で主ASIOとレート・ブロック長を選び「設定を適用」。メーカー設定を開く前は音声を停止する。保存・適用だけでメーカー側の設定は変更しない
3. 適用は検証後に機器を解放し、ポートを再列挙する。運転中なら元のミュート・音量で再開する。主ASIO変更後も経路は端子IDで照合し、対応しない接続は未解決のまま保持する
4. 「ルーティング」で入力から出力へチェックする。主ASIOの全入出力、Windows全入出力、端子別の再生音を表示する。DAW公開用追加機器チェックでマトリクスの端子は隠れない
5. 「音声を開始」で運転。通常起動はミュートON。常用時は前回状態を復元する。TotalMixなどメーカー側ミキサーは別に設定する

Windows出力は接続のある端子だけ開く。使用出力の変更時は短い中断がある。入力と再生音は全端子を取得する。複数入力は加算され、同じ出力へ再生音を戻す循環経路は利用者が管理する

Windows端子は共有形式のチャンネル数を使用する。RMEの再生3ステレオ系統は6入力、Camoなどは通常の入力。ASIOとWindowsの物理対応を推測して統合しない。ドライバーが公開していない物理ポートは追加できない

接続と音量はconfig/router.txtへ保存。旧PC行は旧設定の取り込み元に対応する再生音行へ読み替える。未接続・現在の形式に存在しない経路は未解決として保持する。全端子はbuild/results/router-ports.txtでも確認できる

新規機器・共有形式変更は「機器設定」の「機器一覧を更新」で反映する。保存済み機器設定から一覧を更新するため、未適用の設定は先に適用する。画面の開き直しは不要

「診断」の無音実機テストは共通エンジンをミュートで動かし、最大600秒または共通の停止操作で終了する。人工信号テストは実機を使わず2秒で停止する。テストは常用の自動運転として保存しない。確認音の切替は停止中に行う。診断数値は実測の往復遅延ではない

## 抜き差しと復旧

音声転送中は約2秒間隔で機器一覧の変更とリセット通知を確認する。変更時にセッションを終了・再初期化して同じ端子IDへ再接続する。再初期化中は音声が途切れる。使用者が停止すると再試行も終了する

追加WASAPIが未接続・初期化不可なら、その端子分を無音にして主ASIOを開始できる。運転中の再初期化で主ASIOが開けなければ再接続待ちになり、別の機器を主クロックにしない。起動時に主ASIOが開けない場合はルーティング画面の初期化エラーになり、接続後に開き直す。ASIOのチャンネル数が変わった場合は機器一覧を更新する。再接続時に音量・ミュートの選択は維持する

物理的な抜き差し、全メーカーのASIOリセット復旧は未実機検証。追加機器が開始時に失敗した場合などは再試行待ちになる。新規接続機器は機器設定の「機器一覧を更新」で列挙する

## 別PCで同じ経路を使う

新規利用なら機器設定GUIで選び直す。既存設定を移す場合、同じチャンネル構成のWASAPI機器へIDを割り当て直せる。アプリを閉じ、build/aggregate_host.exe listで移行先IDを調べる

```powershell
./scripts/remap-device.ps1 -OldId '旧端子ID' -NewId '新端子ID' -Preview
./scripts/remap-device.ps1 -OldId '旧端子ID' -NewId '新端子ID'
```

機器設定、PC取り込み元、WASAPI経路、主ASIO対応端子のIDを置換し、build/backupsへ元設定を保存する。任意の別ASIOへの経路移行、チャンネル数が違う機器の自動対応は行わない

## 遅延を揃える

「遅延補正」タブで出力行を選び、追加遅延を0〜2000 msで入力する。±0.1ボタンで微調整でき、「左右を連動」で同じ機器の隣り合うチャンネル対を一緒に変更する。停止中に「手動値を適用」で保存し、次の音声開始から反映する。内部はサンプル単位へ丸める。機器設定のカンマ区切り入力は廃止した

補正値はconfig/router.txtへポートの安定IDで保存する。順番が変わっても同じポートへ対応し、未接続ポートの値も保持する。旧config/aggregate.iniのoutput_delay_msは、安定ID保存がまだない場合だけ読み込み時の列へ対応付け、次の接続保存または遅延適用で移行する。旧値は仮想ASIO側との互換用として残る。新しいポート名別補正はルーティングGUI用で、DAW用仮想ASIO DLLへは反映しない

自動計測の手順:

1. マイクを聴く位置へ固定する。通常音声を転送中でも自動計測ボタンで一時停止できる
2. 「計測マイク」で実入力を選ぶ。Windows再生音ループバックは候補に出ない。RMEの入力、USB・イヤホン付属・Webカメラ等の入力を選べるが、実際に試験音を拾えることが必要
3. 揃える出力をチェックする。初期チェックは現在ルーティングで接続している出力。2チャンネル以上が必要で、ステレオ左右も個別に測る
4. 「試験音で自動計測・適用」を押す。選んだ試験音量（−36/−30/−24/−18/−12/−6 dBFS、既定−24）・500msのスイープ音を1出力ずつ送る。通常のルーティング・音量・ミュートは試験音へ適用しない。出力番号・試行回数・マイクレベルと進捗を表示する
5. 最初に最低60秒、同期を安定させる。直近20秒のバッファ量の傾きを確認し、5回連続で安定するまで自動で待つ（最低時間＋最大120秒で打ち切り）。各出力で予備音1回＋本測定3回→差分計算→補正後の予備音と3回の再計測を行う。残差が0.1msを超えれば追加補正と再測定を最大5回繰り返す。機器は解析・再測定の間も動かし続ける。目安は同期待ち60〜180秒＋各測定の準備2秒・出力数×12秒＋解析時間。測定は初回と確認を合わせ最大7回。RMEの主ASIOクロックを維持する
6. 各出力3回のばらつき2ms以内と、補正後の出力差0.1ms以内を確認できた場合だけ自動保存する。0.1msはサンプル単位で切り下げるため、48kHzでは4サンプル（約0.083ms）以内。毎回、残差と確認回数を表示する。転送中に始めた場合は通常ルーティングへ自動復帰して補正を反映する。停止中に始めた場合は「音声を開始」で反映する。計測中は共通の停止で中止でき、未達・失敗・中止時は保存済み補正を変えない

目標は確認測定の中央値同士の差であり、3回すべての値や常時の出力差が0.1ms以内という保証ではない。マイクの位置・周囲の音・機器の揺れによって目標へ届かず終了する場合がある

計測結果のmsは共通のマイク入力経路を含む値。出力単体の絶対遅延ではない。最も遅い対象出力との差を速い出力へ加えるため、TVの遅延そのものは短縮できない。音声強調やノイズ抑制、反射・周囲の音、Bluetoothの変動で計測できない場合がある。設定変更や抜き差しで到達時間が変わったら再計測する

測定用CLIは指定出力に約−36 dBFS・500msのスイープ音を出す。GUIの試験音量選択はCLIには適用しない。指定入力へ音を戻す配線・マイクが必要。TVスピーカー内部の遅延を含めるには、TVで鳴った音をマイクで測る。入力・出力番号は集約チャンネルの0始まり

```powershell
./build/aggregate_calibrate.exe --play-signal config/aggregate.ini 0 0 build/results/output-0.json
```

単一出力のCLIは予備確認用。複数出力の自動校正には次のコマンドを使う。GUIを「完全終了」し、同じ主ASIOを使う他の処理も停止してから実行する。通常音声と同時には実行しない

## 常用と自動起動

ルーティング画面の「常用：ログイン時に復元／×でトレイへ」を有効にし、音声を開始して必要ならミュートを解除する。接続変更・ミュート・開始／停止は自動保存し、音量はスライダー操作終了時に保存する。「接続を保存」でも保存できる

- ×で閉じてもトレイに残り、分配を継続する。トレイをクリックすると画面を開く。実行ファイルを再度開いても同じ画面を表示する
- トレイの右クリック「終了（音声を停止）」または共通の「完全終了」は完全終了。次に開くと終了前の開始／停止状態とミュート状態を復元する。確認音は復元しない
- 「停止」を押すと、次回も停止状態。常用を解除すると自動起動を解除し、次回は停止・ミュートON
- 現在の利用者のWindowsログイン時に自動起動する。ログイン前のWindowsサービスではない。登録先はHKCUのSoftware/Microsoft/Windows/CurrentVersion/RunのAudioAggregateRouter
- 状態はconfig/resident.txt、接続と音量はconfig/router.txt。実行ファイルを移す前に常用を解除し、移動先で再度有効にする。配布ZIPへこのPCの常用設定は含めない
- 起動時に主ASIOが開けない場合は初期化エラーとなるため、機器接続後に開き直す。運転中の再接続待ちは従来どおり

開発用のbuild/aggregate_router.exe --resident-self-testは出力ミュートで処理を開始し、×が停止イベントを発行せず画面を隠すことを確認して完全終了する。保存設定・自動起動登録は変更しない。結果はbuild/results/resident-self-test.txt

## 配布とDAWの起動

配布ZIPはbuild、config、scripts、ライセンスと説明書を同梱する。このPCの機器ID・接続設定は含めない。展開先の相対配置を保つ。Python・Nodeなどの追加ランタイムは不要。主機器メーカーの64bit ASIOドライバーは別途必要

GUIでのルーティング利用はドライバー登録不要。DAWへ仮想ASIOを登録する場合だけ管理者PowerShellでscripts/register-driver.ps1を実行する。今回の作業ではOSへ登録していない

## 検証範囲

人工信号で多チャンネルPC音、44.1 kHz、独立ルート、出力遅延、ミュート、遅延測定、再起動を検証。実配線での到達・固定遅延、別PC、物理抜き差しは別途検証が必要


開発側の配布ZIP生成：scripts/package.ps1。配布先ではZIPを展開してbuild/aggregate_gui.exeを起動する。インストーラー形式は未作成

## 画面の描画負荷

ホイールで縦、Shift＋ホイールで横スクロールする。横ホイールにも対応する。チェックボックスは表示領域の部品を再利用し、スクロールで行列の端子IDとチェック状態を付け替える。位置変更は一括反映し、旧位置の背景も消去して再描画する。メーターは表示中で文字列が変化したものだけ更新する。音声エンジンの設定や主ASIOクロックは変更しない

開発用の配置検証はbuild/aggregate_router.exe --layout-benchmark。音声を開始せず、保存設定を変更せず、1280×800・1920×1080・3840×2160の480回の配置でセルIDと接続状態を検証し、build/results/layout-benchmark.txtへ配置処理時間を出す。画面の描画完了やマウス操作からの応答時間全体を測るものではない

開発用のbuild/aggregate_router.exe --ui-self-testは4タブの表示切替、機器設定の読み書き一致、不正レート拒否、出力名別の遅延編集・左右連動・不正値拒否を検証する。保存済み設定と音声運転は変更しない。結果はbuild/results/ui-self-test.txt

build/delay_test.exeはポート並び替え、未接続値保持、小数msとサンプル単位の遅延、補正計算、反転した戻り信号、無信号・不安定な計測の拒否、人工エンジンでの中止を検証する。build/aggregate_router.exe --calibration-cancel-self-testは実機ASIOの校正エンジンを起動し、試験音を出す前に中止する。結果はbuild/results/calibration-cancel.txt。これらは実際のスピーカー・マイクによる補正精度の検証を代替しない


## イヤホンの抜き差しとWindowsの既定端子

機器の追加・削除・接続状態・Windows既定端子・ミックス形式の変更をMMDevice通知で検知し、校正や診断中を除いて一覧を再列挙する。通常運転中は一時停止して同じ端子IDの経路・遅延・計測マイク・対象出力を保持して復帰する。未接続の経路は残し、新しい端子へ勝手に付け替えない。未適用の機器設定は保存済み設定へ戻るため、編集後は適用する。校正中の機器変更は結果を拒否し、終了後に一覧を更新する

一覧の[Windows既定]はminiaudioが報告する既定端子。通信用・アプリ個別の出力指定とは異なる場合がある。WindowsやChrome等が再生先をヘッドホンへ変更すると、PC再生音はその再生端子の行に現れる。RMEの行を入力に接続していた場合、その経路へ音は届かない。アプリの入出力は端子ID指定で、Windowsの既定設定を書き換えない。PC音を常に同じ経路で扱う場合は、再生アプリの出力をRME等へ固定するか、専用の仮想再生端子を入口にする構成が必要。後者の仮想WDM端子はこの試作に含まれない

計測が始まらない・音が検出できない場合は遅延補正タブの説明を確認する。失敗した出力番号、相関、計測中のマイク最大レベルを表示し、build/results/calibration-last.txtへ選択名と進捗を保存する。録音そのものはファイルへ保存しない。TV等の物理音量やTotalMixの接続、マイク音量・音声強調はWindows/機器側の状態も確認する

「試験音量」で通常転送の音量とは別に校正音の大きさを選べる。ピークはWindowsへ渡す直前のWASAPIコールバックでも収集し、calibration-last.txtへ端子別の値とフレーム数を記録する。この値はDACや実スピーカーが鳴った証明にはならない。aggregate_host listは端子のWindows音量・ミュートも読み取って表示する。ミュート/音量0なら校正前にエラーを表示する

試験音は500msで、小さな戻り音を周囲の雑音と照合して検出する。マイク音量を上げると雑音も増えるため、最大設定だけで成功するとは限らない。入力が割れる場合は下げる。3回の値が揺れる場合は補正を適用せず、対象出力と実測値を表示する

## CLIで保存済みマイク・複数出力を自動校正する

```powershell
./build/aggregate_calibrate.exe --session config/aggregate.ini config/router.txt build/results/calibration-cli.json -12 60 --apply
```

- GUIで選択・保存したマイクと対象出力を端子IDで照合し、GUIと同じ校正処理を使う
- `-12`は試験音のピークdBFS。CLIは−60〜−6、GUIは−36/−30/−24/−18/−12/−6から選択。値が0に近いほど大きい。既定は−24
- `60`は同期準備の最低秒数。既定60、CLIでは2〜120を指定可能。その後も直近20秒のバッファ量の傾きが各端子0.02ms/秒以下で5回連続するまで待つ。最低時間＋120秒で安定しない場合は補正を保存せず終了する
- `--apply`は成功した補正をconfig/router.txtへ保存。省略時は測定結果JSONだけ保存。測定・補正後の確認に失敗した場合は保存済み補正を変更しない
- GUIまたは別のCLI校正が動いている場合は開始を拒否する。完了後にGUIを起動すると、保存した補正を通常転送へ反映する
- 出力ごとの到達時間・相関・同期診断は標準出力。JSONに測定値・補正値・再測定値を保存する。音声ファイルは保存しない

補正は本アプリから出力する音へ適用する。Windowsや別アプリから機器へ直接送られる音は対象外。通常再生も同期させるには、同じ入力音を本アプリのルーティングから各対象出力へ送る必要がある
